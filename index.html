Solo project

Tanta FCI Academic Assistant (RAG)

Students had no quick way to search the faculty's 74-page scanned bylaws, and answers about prerequisites and grades have to be exact. This assistant answers in Arabic and English using only the bylaws, and cites the article or course behind every answer.

My contribution
Everything: data preparation, retrieval pipeline, API, UI, tests and evaluation.
Technical approach
OCR'd the PDF to Markdown, repaired misread course codes and rewrote the grade tables, then split it into 289 chunks (one per article, course and course description). Retrieval pins the exact line of every course named in the question, then BGE-M3 dense search (20 candidates) and a BGE cross-encoder reranker keep the top 5. A rerank-score threshold makes it refuse instead of guessing, and grade questions are answered from the table in Python. A local qwen2.5:7b model (Ollama, temperature 0) writes the cited answer, served by a FastAPI backend with 12 pytest test functions, a Streamlit chat UI and a Dockerfile.
Results
On 28 hand-written test questions: 24/25 answerable questions correct, the relevant source retrieved and cited for 25/25, and 3/3 out-of-scope questions refused.
Limitations
The test set is small and I wrote it myself, and some fixes were made after seeing failures on those questions, so the score is optimistic. It still fails when a question needs several prerequisites at once. It runs locally only; there is no hosted demo.

Ayn — Personal Travel Planner (AI Agents)

Plans personalised day-by-day trips in Egypt, in Arabic and English, and keeps working when LLM quotas run out.

My contribution
I led the backend: the database schema (SQLAlchemy, 7 tables), sign-up and login with bcrypt and JWT, the setup documentation and 85 automated pytest tests. I also fixed the agent side: the Groq fallback was cutting every plan short, so I switched models and sized the output to the trip length; I added real restaurant names from one cached Tavily search per trip; and I built Arabic translation that never translates restaurant, hotel or airline names.
Built by teammates
The CrewAI multi-agent design and the React frontend.
Technical approach
CrewAI agents on Gemini, falling back to Groq and then to templates, behind a FastAPI and SQLite backend.
Results
Deployed as a live web app. In a manual test of a 4-day Dahab trip, 6/6 meals named real restaurants (a single check, not a benchmark).
Limitations
Depends on free-tier LLM and search quotas, and plan quality was checked manually rather than against a test set.

Solo project

Trip Price Prediction

Predicts ride prices from trip, vehicle and weather features.

My contribution
Everything: cleaning, modelling, evaluation and deployment.
Technical approach
About 100K Uber/Lyft ride records and a scikit-learn preprocessing pipeline. Compared linear regression, random forest, gradient boosting, XGBoost and a neural network, and used KMeans and DBSCAN to explore ride patterns and pricing anomalies. Served with FastAPI and Streamlit on Hugging Face Spaces.
Results
XGBoost: MAE ≈ 1.36 with route-grouped 5-fold cross-validation (no route appears in both training and test data). On a random 80/20 holdout: MAE 1.20 and RMSE 1.84, against a linear-regression baseline of MAE 2.23.
Limitations
The random holdout shares routes with the training data and the hyperparameters were tuned on the full dataset, so 1.36 is the more realistic number. The demo sleeps when idle and takes a moment to wake up.
